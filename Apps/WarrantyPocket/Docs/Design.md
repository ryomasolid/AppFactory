# WarrantyPocket（保証書ポケット）— 設計・画面構成

家電や持ち物の保証書・レシート・取扱説明書を写真でまとめ、保証が切れる前に通知するアプリ。
掲載文は `Store/ASO.md` を参照。

## 1. 方針

- **撮るだけで登録が終わる**。保証書アプリは「最初の5件を入れる手間」で死ぬ。
  レシートを撮ったら購入日・金額・店名を読み取って入力欄に入れ、ユーザーは商品名を打つだけにする。
- **壊れたその場で出せる**。一番使われるのは「登録時」と「壊れた時」。後者は数年後なので、
  検索（商品名・メーカー・型番・シリアル）と写真の拡大表示を速くする。
- **日本の買い方に合わせる**。メーカー保証（1年）と量販店の延長保証（5年・10年）は
  期限も窓口も違うので、別々に持って別々に通知する。
- **端末内で完結**。写真には住所・氏名・カード番号の下4桁が写る。文字認識もオンデバイス（Vision）、
  外部送信なし、アカウントなし。写真ライブラリの全体アクセスも求めない（`PhotosPicker` は許可不要）。

## 2. 技術構成（既存アプリからの流用）

| 部品 | 流用元 | 備考 |
| --- | --- | --- |
| Tuist `Project.swift` / `Tuist/Package.swift` | CarLog | iPhone 専用・縦固定・AdMob 依存。`NSCameraUsageDescription` を追加 |
| SwiftData + `@Observable` | 全アプリ | iOS 17 / Swift 6 strict concurrency |
| `StoreManager`（StoreKit 2 買い切り） | CarLog | プロダクトIDのみ差し替え |
| `ConsentManager`（UMP → ATT → AdMob） | CarLog | そのまま |
| `BannerAdView` / `Theme` | CarLog | ユニットID・色のみ差し替え |
| `Launch`（起動引数によるデモ/スクショ） | CarLog | 引数名を揃える |
| `NotificationScheduler` の「全消し→組み直し」方式 | CarLog | 件数が多くなりうるので**予算60件**を足す（§5） |
| `CSVExport` | CarLog | 列だけ差し替え |

新規に書くのは **文字認識（`TextRecognizer`）・レシート解析（`ReceiptParser`）・保証期限（`WarrantyTerm`）・
書類カメラ（`DocumentScannerView`）・PDF書き出し（`PDFExport`）**。

## 3. データモデル（SwiftData）

```
Item 1 ──< Attachment   保証書・レシート・取説などの写真
```

### Item（登録する商品）
| プロパティ | 型 | 意味 |
| --- | --- | --- |
| `id` | UUID | 通知識別子 |
| `name` | String | 「リビングのエアコン」など表示名（必須） |
| `maker` / `modelNumber` / `serialNumber` | String | 任意。検索対象 |
| `categoryRaw` | String | `ItemCategory`（キッチン家電／生活家電／空調／AV／PC・スマホ／カメラ／家具／その他） |
| `purchaseDate` | Date | 保証の起算日（必須） |
| `price` | Int? | 円 |
| `storeName` | String | 購入店 |
| `warrantyMonths` | Int? | メーカー保証の月数。既定 12。「なし」は nil |
| `extendedWarrantyMonths` | Int? | 延長保証の月数（60 など）。起算日は購入日 |
| `extendedWarrantyProvider` | String | 「ヨドバシ」など延長保証の窓口 |
| `note` | String | 任意 |
| `isArchived` | Bool | 手放した／捨てた。通知と一覧から外す（写真は残す） |
| `createdAt` | Date | 並び順 |

### Attachment（写真）
`id` / `kindRaw`（`AttachmentKind`: 保証書／レシート／取扱説明書／その他）/
`imageData`（`@Attribute(.externalStorage)`・長辺2000pxのJPEG）/ `thumbnailData`（長辺300px）/ `createdAt` / `item`

写真は SwiftData の外部ストレージに持つ（ファイルパス管理を自前でしない＝削除漏れが起きない）。
一覧ではサムネイルだけを読む。

## 4. ロジック（アプリの中身）

すべて純粋関数として `Sources/Services` に置き、SwiftData・Vision に依存させない（テストのため）。

### 4.1 保証期限（`WarrantyTerm`）

「お買い上げ日から1年間」は**購入日を含めて1年**なので、最終日 = 購入日 + 12か月 − 1日。
その日の終わりまで有効。

| 状態 | 条件 |
| --- | --- |
| `.active` | 今日 ≤ 最終日 − 30日 |
| `.soon` | 最終日まで30日以内（当日を含む） |
| `.expired` | 最終日を過ぎた |
| `.none` | 保証が設定されていない |

- 月末の購入は `Calendar.date(byAdding:)` が月末に丸める挙動に揃える（1/31 + 1か月 = 2/28 → 最終日 2/27）。テストで固定する。
- 商品全体の状態は「メーカー保証と延長保証のうち、まだ有効で最終日が遅いほう」。
  延長保証がある商品は、メーカー保証が切れても `.active` のまま。
- 残りの表示は「あと 3年2か月」「あと 12日」「本日まで」「2025/3/1 に終了」。

### 4.2 レシート解析（`ReceiptParser`）

入力は認識結果の行の配列（上から順）。出力は候補（無ければ nil）。**確信の無い値は入れない**。

- **購入日**: `2026年9月14日` / `2026/09/14` / `2026-9-14` / `26.09.14` / `R8.9.14` / `令和8年9月14日`。
  未来日と10年以上前は捨てる。複数あれば「日付の後ろに時刻がある行」を優先（レシートの発行日時）、
  それも無ければ最初の行。
- **金額**: `合計` `お買上` `お支払` `総額` `税込` を含む行（または直後の行）の最大金額。
  `¥12,800` `12,800円` `\12800` と全角数字に対応。`お預り` `お釣り` `ポイント` を含む行は除外。
  キーワードの行が無ければ入れない（最大金額を当てずっぽうに入れると、お預り金額を拾う）。
- **店名**: 先頭3行のうち、日付・電話番号・金額・URL を含まない最も長い行。
  `株式会社` 等は残す。確信が低いので入力欄には入れ、**読み取った値は薄い色の「読み取り」ラベル**で示す。

### 4.3 無料版の上限（`ProLimits`）

| | 無料 | Pro（買い切り ¥480） |
| --- | --- | --- |
| 登録できる商品 | 10件 | 無制限 |
| 写真・読み取り | **無制限** | 無制限 |
| 期限の通知 | **使える** | 使える |
| PDF / CSV 書き出し | × | ○ |
| 広告 | 表示 | 非表示 |

アーカイブした商品も件数に数える（数えないと「アーカイブして追加」で無限に使える）。
一家の家電は20〜30点あるので、11件目で購入の動機が生まれる。
通知と読み取りは塞がない。ここを塞ぐと「撮るだけ」「知らせてくれる」という価値が伝わる前に離脱する。

## 5. 通知設計

- 各商品のメーカー保証・延長保証それぞれについて、最終日の **30日前** と **7日前** の
  設定時刻（既定 9:00）に `UNCalendarNotificationTrigger`（非繰り返し）で予約。
  何日前に通知するかは設定で変えられる（30/7 の2回・7のみ・オフ）。
- 本文は根拠を書く: 「エアコン（リビング）のメーカー保証が 10月14日 で終了します（2025/10/15 購入・1年）。」
- **iOS の予約上限は64件**。Pro で商品が増えると超えるので、発火日の近い順に**60件まで**予約する。
  遠い期限は、アプリを開いたとき（`scenePhase == .active`）の組み直しで順に入る。
  保証期限は年単位で先の話なので、BGTask なしで取りこぼさない。
- 組み直しのタイミング: 起動・アクティブ化／保存／削除／アーカイブ／通知設定の変更。

## 6. 画面構成

タブ3つ（一覧／期限／設定）。バナー広告は全タブ共通で最下部に1つ。

### 6.1 オンボーディング（`fullScreenCover`／初回のみ）
1. 価値の説明（「壊れたときに、保証書がすぐ出てくる」）
2. 撮るだけで読み取れること（サンプルのレシート→入力欄へのアニメーション）
3. 通知の許可（30日前と7日前にお知らせ）

### 6.2 一覧（`ItemListView`）— ホーム
- 上部カード: **保証中 N件**／まもなく終了 M件（タップで期限タブ）
- 検索バー（`searchable`：商品名・メーカー・型番・シリアル・店名）
- カテゴリのチップで絞り込み
- 行: サムネイル・商品名・メーカー/型番・状態バッジ（「あと1年2か月」「あと12日」「終了」）
- 右下の大きな **「撮影して追加」** ボタン（メニュー: 書類をスキャン／写真から選ぶ／手で入力）
- 空の状態: 「まずは最近買った家電のレシートを撮ってみましょう」＋撮影ボタン

### 6.3 追加・編集（`ItemEditorView`）
- 上部に撮った写真のサムネイル列（種類を長押しで変更、追加・削除）
- 読み取った値が入った欄には「読み取り」ラベル。触ったら消える
- 商品名（必須・フォーカス）→ カテゴリ → 購入日 → 金額 → 店名 → メーカー保証（なし/6か月/1年/2年/3年/5年/カスタム）
  → 延長保証（なし/3年/5年/10年/カスタム＋窓口）→ メーカー・型番・シリアル → メモ
- 保存時に最終日のプレビュー「メーカー保証 2027/9/13 まで・延長保証 2031/9/13 まで」

### 6.4 詳細（`ItemDetailView`）
- 写真のカルーセル（タップで全画面・ピンチ拡大。修理窓口で見せる用）
- 保証の残りバー2本（メーカー／延長）
- 情報（購入日・金額・店・型番・シリアルはタップでコピー）
- 「手放した」（アーカイブ）・編集・削除

### 6.5 期限（`TimelineView`）
- まもなく終了 → 保証中（終了日の近い順）→ 終了（最近終わった順）のセクション
- 各行に終了日と残り。延長保証がある商品は2行ぶん（メーカー／延長）出る

### 6.6 設定
通知のタイミング（30日前と7日前／7日前のみ／オフ）と時刻、アーカイブした商品、
PDF・CSV書き出し（Pro）、Pro 購入・復元、プライバシーポリシー、問い合わせ。

## 7. 書き出し（Pro）

- **PDF**: 商品ごとに1ページ（情報＋保証書/レシートの写真を縮小して並べる）。先頭に一覧表。
  用途は引越し・火災保険の請求・家族への共有。`UIGraphicsPDFRenderer` で A4。
- **CSV**: 商品名・カテゴリ・メーカー・型番・シリアル・購入日・金額・店・メーカー保証終了日・延長保証終了日・メモ。
  UTF-8 BOM 付き（Excel で文字化けしない）。

## 8. スクショ用の起動引数（`Launch.swift`）

| 引数 | 効果 |
| --- | --- |
| `-demo` | デモ商品（エアコン・冷蔵庫・洗濯機・ドラム式…12件、写真はコードで描いたレシート画像）を投入 |
| `-hideAds` | バナーと同意/ATT フローを止める |
| `-showPaywall` | 起動直後にペイウォール |
| `-forceOnboarding` / `-onboardingStep <n>` | オンボーディングの強制表示・開始ページ |
| `-startTab <name>` | `timeline` / `settings` |
| `-showScanResult` | デモのレシート画像を読み取った状態の追加画面 |
| `-showDetail` | デモのエアコンの詳細画面 |
| `-searchText <text>` | 一覧の検索欄に文字を入れた状態 |

デモのレシート画像は実在の店舗名・ロゴを使わない（「サンプル電機 駅前店」など）。

## 9. v1 スコープ

**入れる**: 写真（スキャン・ライブラリ）・レシート読み取り・メーカー/延長保証・通知・検索・カテゴリ・
アーカイブ・PDF/CSV書き出し（Pro）・課金・広告・オンボーディング。

**入れない（v1.1 以降）**: iCloud 同期・家族共有、Widget、バーコードで型番入力、取説PDFの取り込み（ファイル）、
修理履歴、買い替え目安（耐用年数）、英語対応。

## 10. リスクと対策

| リスク | 対策 |
| --- | --- |
| 読み取りの誤り（お預り金額を合計と取る等） | キーワード行が無ければ入れない。読み取った値に「読み取り」ラベルを付けて確認を促す |
| 写真で容量が膨らむ | 長辺2000px・JPEG 0.8 に縮小して保存。1枚 300〜600KB |
| トリセツなど大手が強い | 取説DBでは勝負しない。「保証書の写真を撮って置いておく」一点に絞り、撮るだけ登録と延長保証で差別化 |
| 通知の64件上限 | 近い順に60件だけ予約し、アクティブ化のたびに組み直す |
| 写真に個人情報が写る | 端末内のみ・外部送信なしを掲載文とプライバシーポリシーで明示 |

## 11. ビルド・テスト

```sh
cd Apps/WarrantyPocket
tuist install && tuist generate --no-open
xcodebuild -workspace WarrantyPocket.xcworkspace -scheme WarrantyPocket \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```

- `Tuist.swift` は `fullHandle` を持たない（Tuist のクラウド機能を使わない）ので、`tuist auth login` なしで generate できる。
- テストは Swift Testing（`WarrantyPocket/Tests`・44件）。保証期限・レシート解析（行のまとめ方を含む）・
  通知計画（60件の予算含む）・無料版の上限・表示形式・検索・CSV を純粋関数として固定している。
  デモのレシート画像に描く文字列が正しく読み取れることもテストしている（スクショの読み取り結果が本物と同じになる）。
- アイコンは `swift Store/makeicon.swift WarrantyPocket/Resources/Assets.xcassets/AppIcon.appiconset/icon.png` で再生成。
- スクショは起動引数（`Store/ASO.md` の構成）で iPhone 17 Pro Max（6.9"）から撮り、`sips -z 2688 1242` で
  `Store/screenshots-65/` を作る。IAP 審査用は 6.5" のペイウォールを JPEG にしたもの（`Store/iap-review/`）。
- シミュレータには書類スキャン（VisionKit）が無いので、「書類をスキャン」はメニューに出ない。実機で確認する。
