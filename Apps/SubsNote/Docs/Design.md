# SubsNote（サブスク帳）— 設計・画面構成

契約中のサブスクの「月いくら払っているか」と「次にいつ引き落とされるか」を1画面にまとめ、
更新日と無料体験の終了日の前に通知するアプリ。掲載文は `Store/ASO.md` を参照。

> 実装状況（2026-09-14）: v1 スコープを実装済み（Tuist・全画面・通知＋BG組み直し・課金・広告）。テスト 41 件が通る。
> シミュレータでデモ表示を確認済み。未確認: 実機での通知の発火・BGAppRefreshTask、プリセット料金の裏取り。
> AdMob は未作成のため、アプリID・バナーともテストIDのまま（`Project.swift` / `BannerAdView.swift` の TODO）。

## 1. 方針

- **解約し忘れを防ぐことが価値の中心**。一番お金を失うのは「無料体験のまま忘れて本契約になる」ことと
  「年払いの自動更新」。どちらも年に数回しか起きないので記憶に残らない。ここを通知で取る。
- **登録は1件10秒**。サービス名を検索して選ぶと、よくある料金・支払い周期・解約の手順が入る。
  ユーザーは金額と次回の支払日を確かめて保存するだけ。
- **合計を実感させる**。月払い・年払い・週払いが混ざっていても「月あたり ¥8,420／年 ¥101,040／1日 ¥277」に
  そろえて見せる。「こんなに払っていた」が解約の動機になり、アプリを開く理由にもなる。
- **日本の払い方に合わせる**。支払い方法（カード・App Store・Google Play・キャリア決済・Amazon・PayPay など）ごとに
  解約する場所が違うので、支払い方法ごとの合計と「どこで解約するか」を持つ。
- **端末内で完結**。銀行・カード連携はしない（Rocket Money 型は日本で信用されにくく、審査・保守も重い）。
  アカウントなし、外部送信なし。

## 3. データモデル（SwiftData）

```
Subscription   1件のサブスク（履歴テーブルは v1 では持たない）
```

| --- | --- | --- |

## 4. ロジック（アプリの中身）

すべて純粋関数として `Sources/Services` に置き、SwiftData に依存させない（テストのため）。

### 4.1 支払日（`BillingSchedule`）

- n 回目の支払日 = `anchorDate` に `cycleInterval × n` 単位を足した日。**必ず起点から数える**
  （前回の支払日に足していくと、1/31 → 2/28 → 3/28 と日がずれていく）。
  1/31 起点の月払いは 1/31 → 2/28 → 3/31 → 4/30。テストで固定する。
- 閏年の 2/29 起点の年払いは、平年は 2/28。
- 「次回の支払日」= 今日以降で最初の支払日（今日が支払日なら今日）。
- 無料体験中（今日 ≤ `trialEndDate`）は、次回の支払日 = 体験最終日の翌日、状態は `.trial`。
- 状態: `.trial`（体験中）／`.active`／`.cancelled`。

### 4.2 金額の換算（`CostSummary`）

- 月あたり = 週払い `price × 52 ÷ 12 ÷ interval`、月払い `price ÷ interval`、年払い `price ÷ 12 ÷ interval`。
  表示は四捨五入した円。合計は換算前の分数で足してから丸める（1件ずつ丸めて足すと数十円ずれる）。
- 年あたり・1日あたりも同じ方式。
- 体験中のサブスクは合計に**含めない**が、「体験が終わると 月 +¥1,490」と別枠で出す。
- 「今月の支払い」= 今月1日〜末日に来る支払日の実額の合計（換算値ではない）。カレンダーと一致させる。
- 集計の切り口: カテゴリ別・支払い方法別。

### 4.3 サービスのプリセット（`ServicePreset`）

- 国内でよく使われる51件（動画・音楽・Amazon プライム・クラウド・AI・スマホのオプションなど）を
  コードに持つ。各項目: 表示名・読みがな（検索用・ひらがな）・カテゴリ・よくある料金プランの候補・周期・よくある支払い方法。
  料金に自信がない5件（TELASA・Xbox Game Pass・Apple Arcade・Adobe・Claude Pro など）は候補を持たせず、手入力にする。
- **料金は候補として出すだけで、保存前に必ず入力欄で見せる**（値上げで古くなるため）。
  データの最終確認日をファイル先頭にコメントで残す。
- ロゴ画像は使わない（商標）。頭文字とカテゴリ色の丸アイコンで表す。
- 解約手順は「App Store 経由: 設定 > [ユーザ名] > サブスクリプション」のように支払い方法ごとの一般的な手順を基本にし、
  サービス固有の URL は持たない（リンク切れの保守をしない）。

### 4.4 無料版の上限（`ProLimits`）

| | 無料 | Pro（買い切り ¥480） |
| --- | --- | --- |
| 登録できるサブスク | 5件 | 無制限 |
| 更新日・無料体験の通知 | **使える** | 使える |
| 合計（月・年・1日）とカレンダー | **使える** | 使える |
| カテゴリ別・支払い方法別の内訳 | × | ○ |
| CSV 書き出し | × | ○ |
| 広告 | 表示 | 非表示 |

解約済みは件数に**数えない**（解約を記録するほど損をする作りにしない。解約の記録は価値の証拠でもある）。
その代わり、解約済みを「再開」するときに上限を確認する。日本の平均契約数は3〜5件なので、6件目で購入の動機が生まれる。

## 5. 通知設計

- 各サブスクの支払日の **3日前** と **前日**（設定で 7日前／3日前／前日／当日 の組み合わせ・時刻は既定 9:00）に
  `UNCalendarNotificationTrigger`（非繰り返し）で予約。
- 無料体験は **最終日の3日前と前日** に必ず予約する（設定で消せるが既定オン）。本文は強めに書く:
  「無料体験は9月20日まで（あと3日）。続けない場合はそれまでに解約を。9月21日から 月 ¥1,590 の支払いが始まります。」
  体験終了を通知するときは、体験後の初回の支払日の「3日前・前日」は重ねない。60件の枠には体験終了を先に入れる。
- 本文は根拠を書く: 「9月17日に YouTube Premium の支払い（¥1,280・App Store）があります。」
- **iOS の予約上限は64件**。各サブスクの今後の支払日を展開し、発火日の近い順に**60件まで**予約する。
- 月払い20件×2通 = 月40通なので、アプリを開かないと2か月弱で予約が尽きる。
  GomiAlarm と同じく `BGAppRefreshTask` で1日1回程度組み直す＋アクティブ化・保存・削除・設定変更で組み直す。
- 年払いの更新は「7日前」も既定でオン（金額が大きく、解約の判断に時間がかかるため）。

## 6. 画面構成

タブ3つ（ホーム／カレンダー／設定）。バナー広告は全タブ共通で最下部に1つ。

### 6.1 オンボーディング（`fullScreenCover`／初回のみ）
1. 価値の説明（「毎月いくら払っているか、すぐ分かる」）
2. 解約し忘れを防ぐ（無料体験の終了通知の例）
3. 通知の許可

### 6.2 ホーム（`HomeView`）
- 上部カード: **月あたり ¥8,420**（年 ¥101,040・1日 ¥277）／今月の残りの支払い ¥3,280
- 「無料体験中」セクション（あれば最上部・終了日の近い順・残り日数を赤で）
- 「次の支払い」順のリスト。行: 丸アイコン・名前・支払い方法・「9/17（あと3日）」・金額と周期
- 並べ替え（次の支払い順／金額順／名前順）、内訳（カテゴリ別・支払い方法別の横棒。Pro）
- 「解約済み」セクション（折りたたみ・「解約して年 ¥11,760 浮いています」）
- 右下の **「追加」** ボタン
- 空の状態: 「まずはよく使うサービスを1つ追加してみましょう」＋人気のプリセット6つのチップ

### 6.3 追加（`PresetPickerView` → `SubscriptionEditorView`）
- プリセットの検索（名前・読みがな）とカテゴリ別の一覧、「リストにないサービスを追加」
- 編集: 名前 → 金額・周期（プランの候補チップ）→ 次回の支払日（またはこれまでの支払日）→ 無料体験中か（トグル＋最終日）
  → 支払い方法 → カテゴリ → 解約の手順 → メモ
- 保存時にプレビュー「次回 9/17・以後毎月17日・月あたり ¥1,280」

### 6.4 詳細（`SubscriptionDetailView`）
- 金額・周期・次回の支払日・これまでに払った概算（起点から今日までの回数×金額）
- 今後6回の支払日
- 解約の手順（コピー可）、「解約した」ボタン（日付を記録）、編集・削除

### 6.5 カレンダー（`BillingCalendarView`）
- 月表示。支払いのある日に丸アイコン、下に選択日の支払い一覧とその月の合計
- 前月・翌月へスワイプ

### 6.6 設定
通知のタイミングと時刻、体験終了の通知、CSV書き出し（Pro）、Pro 購入・復元、プライバシーポリシー、問い合わせ。

## 7. 書き出し（Pro）

- **CSV**: 名前・カテゴリ・金額・周期・月あたり・年あたり・次回の支払日・支払い方法・無料体験の最終日・状態・解約日・メモ。
  UTF-8 BOM 付き（Excel で文字化けしない）。

**入れる**: プリセット・手入力・週/月/年×間隔・無料体験・支払い方法・通知（BG組み直し含む）・合計と換算・

## 10. リスクと対策

| リスク | 対策 |
| --- | --- |
| 競合が多い（サブスク管理・Costly・SubsHub・Bobby など） | 「無料体験の終了通知を無料で・強めに」「支払い方法ごとの解約場所」「解約で浮いた額」の3点で差をつける。ASO は「解約忘れ」「無料体験」を名前とサブタイトルで取る |
| プリセットの料金が古くなる | 候補として見せるだけで必ず入力欄で確認させる。確認日をコードに残し、アップデートのたびに見直す |
| 通知の64件上限・アプリを開かない | 近い順に60件＋BGAppRefreshTask＋アクティブ化で組み直し |
| 月末・閏年の支払日ずれ | 起点から数える方式に固定し、テストで 1/31・2/29・5/31 を押さえる |
| 他社の商標 | ロゴを使わない。スクショは架空のサービス名 |
| 審査（金融アプリ扱い） | 送金・口座連携なしの記録アプリであることを審査メモに書く。カテゴリはファイナンスで問題ない |

## 11. ビルド・テスト

```sh
cd Apps/SubsNote
tuist install && tuist generate --no-open
xcodebuild -workspace SubsNote.xcworkspace -scheme SubsNote \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```

- テストは Swift Testing。支払日（起点から数える・月末・閏年・間隔・体験終了）・換算（丸め方）・今月の支払い・
  通知計画（60件の予算・体験終了の優先）・無料版の上限（解約済みを数えない）・プリセット検索（読みがな）・CSV を固定する。
- 手順は WarrantyPocket と同じ（アイコンは `Store/makeicon.swift`、スクショは 6.9" から `sips -z 2688 1242` で 6.5" を作る）。
